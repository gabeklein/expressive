`api/` routes. A root `api/` folder beside `app/` serves HTTP routes under `/api`, named as in `app/`: `api/(logout).ts` serves `/api/logout`, `api/photo/[id].ts` serves `/api/photo/:id`, `api/auth/[...].ts` serves `/api/auth/*`, and a folder's `index.ts` serves the folder. A bare-named module (`api/photo/store.ts`) is a helper the routes import - not a route, free to export anything. A module exports `GET`, `POST`, `PUT`, `PATCH`, `DELETE` or `OPTIONS` - HEAD runs `GET`, another method is a 405 with `Allow` - or a `default` that answers every method, where a returned function is a fetch handler called with `(request, env, ctx)`, so `export default () => hono.fetch` mounts an app. A folder `index.ts`'s `default` is its gate, run before everything below it - unmatched paths included - and its Models are in context until the request ends. Routes read the request from `Current`. Matching is exact with no backtracking; an unmatched path is a JSON 404, never the shell - in dev, one that names a helper sitting at that path. The dev server and the build fail on a route with no handler or any other runtime export, a class gate, a misnamed file, something else serving `/api` (`app/api/`, `public/api/`), and a client import from `api/`; the build fails, and a dev save logs, on a helper exporting a verb-named function. Served in dev, on Node and on the fetch target; in dev an edit to a route or its helpers lands on the next request.
